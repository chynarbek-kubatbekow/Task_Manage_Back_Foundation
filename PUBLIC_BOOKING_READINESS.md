# Готовность к будущей онлайн-записи

Внутренний API сотрудников и будущий публичный API должны оставаться раздельными.

- `ClientSerializer` предназначен только для авторизованного рабочего интерфейса и содержит медицинские поля.
- `PublicBookingClientSerializer` уже ограничен ФИО и контактами, но пока намеренно не подключён ни к одному URL.
- Публичная запись не должна принимать `company` из тела запроса: клиника определяется сервером по отдельному публичному идентификатору.
- Перед запуском понадобятся подтверждение телефона, rate limit, защита от повторной отправки и отдельная выдача свободных интервалов без персональных данных сотрудников и пациентов.
- Диагноз, заметки врача, внутренние заметки, список пациентов и история визитов никогда не должны возвращаться публичному сайту.

Сайт самостоятельной записи в текущей версии не реализован и не опубликован.
